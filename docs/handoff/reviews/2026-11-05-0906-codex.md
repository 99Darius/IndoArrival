## Findings

The page checks pass, but the new IndexNow script can exceed its batch limit, resend unchanged pages and report misleading dry-run results. The first two defects were reproduced locally with mocked network responses.

Full review comments:

- [P2] Apply the page ceiling after merging retry URLs — /Users/dariuscheung/Downloads/Antigravity/IndoArrival/scripts/indexnow.mjs:240-240
  When previously unreachable pages are retried alongside new changes, the combined batch can exceed `--ceiling` because only new URLs are checked. A mocked run with ceiling 1, one new page and one retry successfully submitted two pages. Apply the limit to the deduplicated combined batch before fetching or submitting it.

- [P2] Prevent repeat submissions for unchanged date-only entries — /Users/dariuscheung/Downloads/Antigravity/IndoArrival/scripts/indexnow.mjs:62-64
  When the script runs more than once on a page's modification date, converting that date to the end of the day leaves it newer than every successful run that day. The unchanged page is therefore submitted repeatedly, consuming the weekly allowance and potentially blocking genuine updates. Track the last submitted modification value per URL, while still allowing newly discovered pages dated today.

- [P2] Read existing submission state during dry runs — /Users/dariuscheung/Downloads/Antigravity/IndoArrival/scripts/indexnow.mjs:202-202
  With an existing state file, `--dry-run` ignores the last successful run, weekly usage and pending retries. Its reported batch can therefore differ from the real run, including showing submissions that the real run would refuse or omitting pending retries. Read state in both modes and suppress only writes and submissions during a dry run.
