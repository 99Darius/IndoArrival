## Findings

The Thailand recorder can save one traveller's answer under another and lose concurrent recordings across tabs. All 141 tests and TypeScript checks pass, but they do not cover these cases.

Full review comments:

- [P2] Reset correction tracking when a new fill starts — /Users/dariuscheung/Downloads/Antigravity/IndoArrival/extension/src/content/th/recorder.ts:227-231
  If someone edits traveller A's visa, then fills traveller B before the 600 ms correction timer fires, this clears `corrections` but leaves `baselines` and `changed` behind. If B has no saved visa, the next manual edit makes `refresh(corrections)` collect A's visa still on the form and save it under B. Clear the old correction-tracking state when starting another fill, while preserving any active recording state.

- [P2] Serialize draft updates across form tabs — /Users/dariuscheung/Downloads/Antigravity/IndoArrival/extension/src/content/th/recorder.ts:120-124
  When two Thailand tabs record different fields at nearly the same time, both can read the same draft before either write finishes. Each then replaces its entire `fields` array with its own captured answers, so the last write loses the other tab's new field. Reading `draft` here does not prevent that race because its fields are not merged and the read/write pair is not serialized. Route draft updates through the background's shared serialization queue and merge field-level changes there.
