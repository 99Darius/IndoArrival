## Findings

Traveller switching during filling can save corrections under the wrong person. Recording across multiple tabs can also silently overwrite newer answers.

Full review comments:

- [P1] Keep the filled traveller ID fixed during replay — /Users/dariuscheung/Downloads/Antigravity/ThaiArrival/extension/src/content/panel.ts:111-112
  If the user switches travellers in the popup while the panel is filling, the storage listener changes `travellerId` before this line runs. The form still contains the original traveller's answers, but subsequent corrections are assigned to the newly selected traveller and accepted by `learnUpdate`. Capture the traveller ID before awaiting `fillStep` and use that same ID when emitting `REPLAYED`.

- [P2] Merge recording changes without overwriting other tabs — /Users/dariuscheung/Downloads/Antigravity/ThaiArrival/extension/src/content/recorder.ts:79-79
  When two form tabs are open during recording, each keeps its own captured values, and this merge ignores newer draft values for keys already present locally. A later flush in the other tab refreshes those keys from its stale form and writes the entire draft back, silently replacing answers just recorded in the first tab. Send only locally edited fields through a serialized background merge, rather than letting every tab replace the shared draft.
